CI проверяет логику, замороженный exe и закрытие окон на заглушках, но **не заменяет** проверку на настоящем Windows и телефоне.

номера, контакты, SMS и пути.

## 1. Установка и состав
- [ ] Чистая Windows x64: запустить `SymPortBridge-Setup`, затем Bridge. Python, pip, Gammu, VC++ вручную **не ставились**.
- [ ] `SymPortBridge.exe --self-test --report self-test.json`: `components` — все обязательные `true`, `ca_pinning` и `doctor` — `passed`.
- [ ] Обновление Bridge: настройки, ключ DPAPI и закреплённые сертификаты (`trusted-ca`) сохранились.

## 2. Diagnostics (повторить 10 раз)
- [ ] Трей → Diagnostics: окно открывается быстро, меню трея отвечает.
- [ ] Закрытие: кнопка «Закрыть», Esc, Enter, крестик — каждый по разу несколько раз; повторный клик по Diagnostics при открытом окне не плодит окна.
- [ ] После закрытия Bridge продолжает отвечать, сканировать и держать связь с SymPort.
- [ ] «Копировать диагностику»: в тексте нет IMEI, серийных номеров, PnP instance ID, путей, адресов, ключей.

## 3a. MTP (Windows Portable Devices) — не проверено на устройстве
- [ ] E72 в режиме, где Windows показывает его как WPD (`0421:0223`): Doctor показывает `mtp-files` и маршрут «Files over MTP: available, read-only» (если нет — приложить результат кнопки «Копировать диагностику»).
- [ ] SymPort → Файлы: появляется подключение «Nokia (Windows Portable Device)», корень показывает «Phone memory»/«Memory card».
- [ ] Список папки и скачивание небольшого файла (картинка, текст): содержимое совпадает; временная копия удалена (`%TEMP%\symport-wpd-*` нет).
- [ ] Загрузка, удаление, создание папки по MTP отклоняются понятным сообщением (не реализованы).
- [ ] Контакты/календарь/SMS через это подключение недоступны и не обещаются; модель/прошивка не показываются.
- [ ] Заблокированный телефон: подключение «не подключено» без хранилищ, понятная подсказка.
- [ ] Windows 11, E72 с общим драйвером MTP (`WUDFWpdMtp`, устройство `S60 Handset`): Shell-путь **без** `vid_0421` (`…usb#ms_comp_mtp#<id>#…`) — устройство всё равно в списке: скрипт берёт PnP `USB\MS_COMP_MTP\<ID>` и проверяет, что его родитель (`DEVPKEY_Device_Parent`) — Nokia USB (`USB\VID_0421&PID_xxxx…`). Если список пуст — приложить версию Windows и (без серийных номеров) вывод `Get-PnpDeviceProperty -KeyName DEVPKEY_Device_Parent` для этого устройства.
- [ ] Чужое MTP-устройство (другой производитель) в списке **не** появляется; по имени `S60 Handset` без Nokia-родителя ничего не распознаётся.
- [ ] Порядок/индексы: при нескольких переносных устройствах `index` в листинге и скачивании указывает на то же устройство, что и в пробе.
- [ ] В «Копировать диагностику», журнале и браузере нет PnP instance id, серийного номера и Shell-пути.

## 3b. Nokia-специфичное подключение Gammu без COM (DKU-2) — не проверено
- [ ] Драйвер Nokia Connectivity Cable установлен вручную, режим PC Suite: после «Повторить поиск» Doctor показывает `identified:dku2` или `identified:dku2phonet` либо честно «no response».
- [ ] При удачной идентификации: какие операции чтения реально работают (контакты/календарь), без записи. Идентификация сама по себе ничего не доказывает.
- [ ] Повтор пробы только при смене набора USB или по «Повторить поиск» (журнал/окно не зависают на ~40 с).

## 3c. Молчащий COM-порт (Nokia E72, драйвер Nokia CCD, Windows 11) — не проверено
- [ ] COM «Nokia E72 USB Modem» (AT-порт) и «Nokia E72 USB Serial Port» (`IF_JAVACOMM`): Doctor показывает один Nokia COM-порт и «(+1 Java comm, not used)»; Java comm-порт Bridge не открывает (проверить, например, Process Monitor/PortMon).
- [ ] Пока телефон молчит: статус `com-silent`, в тексте действия есть результат пробы DKU-2; запись в COM8 из другой программы **не** падает с `semaphore timeout` (раньше падала, пока Bridge запущен).
- [ ] Интервал опроса растёт 30 → 60 → … → 10 мин (видно по редким открытиям порта), сбрасывается при переподключении кабеля и по «Повторить поиск».
- [ ] После «выключить/включить телефон, выбрать PC Suite после загрузки» — отвечает ли AT (`AT`, `ATI`) и идентифицирует ли Gammu; если нет — что показала проба DKU-2.
- [ ] Закрыть Bridge посреди идентификации: нет процесса `--gammu-worker` и открытого порта после выхода, нет окна с ошибкой.

## 3d. Маршрут USB OBEX (Nokia PCCS) — проверено вручную на одном E72, в CI не проверяется
- [ ] E72, режим PC Suite, PC Suite закрыт: в списке подключений появляется «Nokia E72 / USB OBEX», контакты и календарь `available` (до этого — нет).
- [ ] Чтение контактов и календаря возвращает те же записи, что на экране телефона; кириллица в именах и в названиях событий верна.
- [ ] Nokia PC Suite открыт: маршрут `busy`, подсказка «закройте Nokia PC Suite»; после закрытия и повторной попытки — чтение работает (первый Connect мог не пройти).
- [ ] Телефон заблокирован клавиатурой: что показывает маршрут (молчит/читает), и что видно в журнале.
- [ ] Много записей (≥ 100 контактов, ≥ 50 событий): `ReadItems` по 20 id работает, число записей совпадает; при расхождении — записать, где обрыв.
- [ ] Другие модели S60 3rd/5th (E52, E71, N97…): отметить результат отдельно, не переносить с E72.
- [ ] Закрыть Bridge посреди чтения: нет открытого хранилища на телефоне (PC Suite потом открывается без ошибки), нет занятого интерфейса.
- [ ] В Doctor, журнале, скопированной диагностике и ответах API нет IMEI, серийного номера, пути интерфейса `\\?\nmwcd#…`.

## 3e. Выбор маршрута (`transport_preference`) — не проверено на устройстве
- [ ] E72, Gammu молчит (COM8 / DKU-2 → `ERR_DEVICENOTEXIST`), USB OBEX работает: Doctor показывает код Gammu и подсказку «известное ограничение x64-сборки Gammu»; контакты и календарь в режиме `auto` читаются по USB OBEX; в приложении баннер «Gammu не достучался…» и кнопка «Переключиться».
- [ ] «Переключиться» только меняет выбранное подключение; в журнале операций появляется `connection-select`, телефон ничего не получает (PC Suite не видит новых обращений).
- [ ] Режимы `gammu` / `pccs` / `mtp` в окне настроек: каждый использует только свой маршрут и сообщает, чего не умеет; после сохранения новый выбор виден в Doctor не позже чем через ~5 с.
- [ ] Идёт чтение контактов по USB OBEX: смена настройки не прерывает чтение, применяется после него.
- [ ] Gammu потом «оживает» (verified): в `auto` контакты и календарь возвращаются на Gammu, в приложении «Используется USB OBEX» исчезает.

## 4. Связь с NAS (HTTPS Home LAN)
- [ ] Браузер: предупреждение о сертификате, затем (по желанию) установка CA со страницы входа — предупреждение исчезло.
- [ ] «Запросить доступ»: в окне подтверждения виден адрес и начало отпечатка; после «Да» Bridge → `connected`, «сертификат закреплён», **без** установки CA в Windows.
- [ ] Неверный отпечаток/подмена: сопряжение отклоняется.
- [ ] Смена IP NAS и перезапуск SymPort: `tls-hostname` показан отдельно; повторное сопряжение лечит.
- [ ] NAS выключен: `unreachable`; перезапуск SymPort: `lease-missing`/`lease-expired`; новый запрос доступа: `bad-token` показан понятно.
- [ ] Системный прокси Windows: связь с адресом домашней сети идёт напрямую.
